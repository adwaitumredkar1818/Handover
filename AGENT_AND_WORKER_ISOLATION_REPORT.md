# Agent and Worker Isolation Report
## Intelligent Project Knowledge Reconstruction & Handover Platform ("The Handover")
### Specialized Agents, Dynamic Workers & Deterministic Tool Isolation

---

## 1. Architectural Scope

In **The Handover**, investigations across complex domains (Deep Research, Deep Think, Deep Extract) instantiate temporary specialized execution instances. To prevent unauthorized privilege escalation or cross-project data leakage, all workers, tools, and registries are governed by strict isolation contracts.

---

## 2. Dynamic Agent Worker Isolation

### Immutable Project Context Binding:
In `backend/app/services/ai/agent_factory.py`:
- `DynamicAgentWorker` receives `project_ctx: ProjectContext` upon instantiation.
- `_project_ctx` is stored privately and exposed only via a read-only property `@property project_ctx`.
- Re-assignment or modification of `project_ctx` is programmatically blocked.

### Task Execution Boundaries:
```python
def execute_task(
    self,
    task_description: str,
    evidence_context: str,
    target_project_id: uuid.UUID | None = None,
) -> AgentFinding:
    if target_project_id is not None and target_project_id != self._project_ctx.project.id:
        raise ForbiddenError(
            f"Agent worker cannot execute task across projects...",
            code="CROSS_PROJECT_AGENT_FORBIDDEN",
        )
```
- Workers cannot switch project identities.
- Workers cannot accept tasks or subqueries targeted at other project IDs.
- Findings generated by workers inherit the exact `project_id` and cannot be leaked into another project's investigation state.

## 3. Deterministic Tool Registry Sandbox

In `backend/app/services/ai/tools.py`:
`ToolRegistry.execute_tool()` enforces:
1. **Mandatory ProjectContext**: Rejects any tool call where `project_ctx` is `None` with `PROJECT_CONTEXT_REQUIRED`.
2. **Strict Project Argument Validation**: If an argument dictionary contains a `project_id`, it must strictly equal `str(project_ctx.project.id)`. Any mismatch raises `ForbiddenError(code="CROSS_PROJECT_TOOL_FORBIDDEN")`.
3. **Host Filesystem Protection**: Arguments are inspected for host filesystem paths (e.g., `C:\Windows\`, `C:\Users\`, `/etc/`, `/home/`). Any attempt to inspect host directories raises `ForbiddenError(code="ENV_INSPECTION_FORBIDDEN")`.
4. **RBAC Permission Gate**: Every tool requires an explicit permission code (e.g. `assistant.chat`, `project.manage`). If the principal lacks the permission, execution fails closed.
5. **Consequential Action Gate & Idempotency**: Consequential operations require human approval and execute with distributed Redis + PostgreSQL idempotency locks.

---

## 4. Working Memory Isolation

In `backend/app/services/ai/memory.py`:
- `ProjectWorkingMemoryService` partitions all derived insights by `project_id: uuid.UUID`.
- `get_working_memory(project_id)` strictly queries the active project's partition.
- `clear_project_memory(project_id)` enables clean state resets on project switches.
- `record_derived_insight()` runs a privacy filter to prevent developer workstation specs from being stored as project memory.
